# Purpose

This document defines the visual language and user experience principles of Study.et.

The design system exists to create a consistent, accessible, and timeless interface that prioritizes information over decoration.

---

# Design Philosophy

Study.et should feel like a modern academic library.

Users visit the platform to discover educational opportunities—not to admire visual effects.

Every design decision should increase clarity, reduce cognitive load, and help users make informed decisions.

---

# Core Design Principles

## Content First

Content is the product.

Design exists to support content, never compete with it.

---

## Calm Interface

The interface should feel:

- Calm
- Neutral
- Professional
- Trustworthy

Avoid unnecessary visual noise.

---

## Simplicity

Prefer fewer elements with better spacing.

Every component should have a clear purpose.

---

## Consistency

The same interaction should behave the same way everywhere.

Buttons, cards, spacing, typography, and navigation should follow shared patterns.

---

# Brand Personality

Study.et is:

- Educational
- Modern
- Honest
- Neutral
- Helpful

It is **not**:

- Corporate
- Flashy
- Trendy
- Playful
- Promotional

---

# Typography

Primary Font:

- Geist

Typography should communicate hierarchy using:

- Size
- Weight
- Spacing

Avoid excessive font variations.

---

# Color Philosophy

The interface should remain visually neutral.

Universities bring their own identity through logos and imagery.

Application colors should support readability rather than branding.

Primary interface colors:

- Background
- Surface
- Border
- Text
- Accent

Avoid rainbow color palettes.

---

# Spacing

Whitespace is an interface element.

Use consistent spacing throughout the application.

Avoid crowded layouts.

---

# Layout

Homepage:

- Navigation
- Hero
- Search
- Popular Universities
- Directory
- Footer

University Pages:

- Hero
- Overview
- Academic Units
- Admissions (when available)
- Social Links
- Footer

---

# Components

Core components:

- Navigation
- Search Box
- University Card
- Filter Panel
- Badge
- Tag
- Section Header
- Footer

Components should be reusable.

---

# Cards

University cards should include:

- Logo / Cover
- Name
- Location
- Institution Type

Cards should remain clean and uncluttered.

---

# Icons

Icons support text.

Icons should never replace important labels.

Use a consistent icon library throughout the project.

---

# Motion

Motion should communicate.

Allowed:

- Hover states
- Smooth transitions
- Focus indicators

Avoid:

- Decorative animations
- Pulsing effects
- Auto-playing movement

---

# Accessibility

Every interface must:

- Support keyboard navigation
- Have visible focus states
- Meet WCAG contrast recommendations
- Include meaningful alt text

Accessibility is a requirement, not an enhancement.

---

# Responsive Design

Study.et should work well on:

- Mobile
- Tablet
- Desktop

Content should remain readable regardless of screen size.

---

# Images

University images should:

- Load efficiently
- Preserve aspect ratio
- Represent institutions accurately

Decorative imagery should be minimal.

---

# Empty States

Every empty state should help users understand what to do next.

Never display blank screens.

---

# Error States

Errors should:

- Explain what happened
- Suggest the next action
- Avoid technical jargon

---

# Future Design Evolution

Future additions may include:

- Dark Mode
- Theme customization
- Interactive campus maps
- Comparison views

These additions should extend—not replace—the existing design language.

---

# Design Review Checklist

Before merging UI changes:

- Does this improve clarity?
- Is the layout consistent?
- Is the interface accessible?
- Does it follow existing patterns?
- Does it prioritize content?

If any answer is "No", revise the implementation.

---

# Revision Policy

This document is part of the Study.et Handbook and should evolve alongside the product while preserving its core design philosophy.
